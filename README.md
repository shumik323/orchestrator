# orchestrator

`orchestrator` выполняет задачи из файла-очереди по одной, запуская на каждой AI-агента без интерфейса. Похоже на CI-джобу: взять задание, сделать работу, прогнать проверки, отдать результат. Разница в том, что работу делает языковая модель, а результатом становится git-ветка с диффом.

Мерж и ревью остаются за человеком. Раннер до основной ветки не дотягивается.

## Как это выглядит

Настоящий прогон, вывод не сокращён:

```
$ ./scripts/run-task.sh projects/demo.conf t-42
▶ задача t-42  orc/t-42 → main
  ├─ клон main …
  │  · из .harness.conf: гейт [bash -n deploy.sh], зоны [dist]
  │  ✓ клон (0с)
  ├─ генератор, дедлайн 60с …
  │  ✓ генератор (3с)
  │  · стоимость 0.09 USD, ходов 4
  ├─ гейт: bash -n deploy.sh …
  │  ✓ гейт (1с)
  ├─ полный прогон тестов: shellcheck -S info deploy.sh …
  │  ✓ полный прогон тестов (1с)
  │  ✓ push orc/t-42 (2с)
  ╰─ ✓ MR: /tmp/demo/mr/t-42.md (всего 6с)
MR: /tmp/demo/mr/t-42.md
```

Каждая строка попадает в JSONL-лог. Таймлайн прогона и его стоимость потом читаются `jq`, а не поиском по терминалу.

## Зачем это, если можно попросить агента в чате

В чате удобно, пока задача одна. Разница появляется на десятке однотипных: типовые правки после миграции, тесты к существующим компонентам, замечания линтера, замена устаревшего API.

Три вещи, которых у чата нет.

**Результат не показывается, пока не прошёл проверки проекта.** Агент не отчитывается словами. Он либо оставил ветку, прошедшую линт и тесты, либо задача помечена `blocked` и рабочий каталог остался для разбора.

**Область работы ограничена машинно, а не просьбой в промпте.** Дифф сверяется со списком разрешённых путей до запуска проверок. Вышел за модуль — прогон останавливается.

**Каждый прогон оставляет цифры.** Стоимость, число ходов модели, время каждой фазы, исход. После двадцати задач видно, сколько стоит класс задач и где петля упирается.

## Статус

Работает один сценарий целиком: одна задача, один прогон, git-репозиторий с настроенными проверками. На таком прогоне агент подавил замечание `shellcheck` в чужом репозитории, проверки прошли, ветка появилась. Обошлось в $1.02 и 12 ходов модели.

Не проверено: push по токену в GitLab или GitHub (все прогоны шли в локальный bare-репозиторий), бэкенды `glab` и `gh`, `REPO_URL` по SSH, параллельные прогоны, поведение при заполненном диске.

Не сделано: очередь из трекера задач, повторные попытки после красных проверок, работа больше чем над одним проектом за раз. Параллельные прогоны одной очереди: файл очереди защищён mkdir-локом, но рабочие каталоги и лимит подписки раннеры не делят — дашборд второй запуск по той же очереди отклоняет, из CLI это на дисциплине.

132 теста, полный прогон одной командой: `./scripts/verify-all.sh` — около 6 минут, большую часть
времени занимают сценарии раннера с настоящими клонами и bare-репозиториями.

## Требования

`bash` 3.2 и новее (системного на macOS достаточно), `git`, `jq`. Для тестов `bats` и `shellcheck`.

Агент по умолчанию — Claude Code CLI на подписке, API-ключ не нужен. Переменная `ORC_GEN_CMD` подменяет его любой командой, поэтому раннер можно гонять и с другим агентом, и с заглушкой в тестах.

## Установка

```bash
git clone <this-repo> && cd orchestrator
./scripts/verify-all.sh          # проверить, что окружение подходит
```

## Использование

```bash
# 1. локальный remote с гардрейлом: push в main отклоняется хуком
./scripts/make-remote.sh /tmp/target.git main

# 2. конфиг проекта
cat > projects/demo.conf <<'EOF'
REPO_URL="/tmp/target.git"
BASE_BRANCH="main"
BRANCH_PREFIX="orc"
GATE_CMD="bash -n deploy.sh"
MR_BACKEND="file"
MR_DIR="/tmp/mr"
QUEUE_FILE="queue/demo.jsonl"
DEADLINE_SEC="900"
MAX_BUDGET_USD="1.00"
REVIEW_TRACKS="A B"        # треки задач с фазой review; пусто — без ревью
REVIEW_BUDGET_USD="2.50"   # на каждый из двух вызовов ревью
WRITE_SCOPE="src/features/x"
# формат коммита бота — под хук проекта; {id} и {title} из задачи
COMMIT_MSG_TEMPLATE="MD-0000: {title} [{id}]"
EOF

# 3. задача в очередь
echo '{"id":"t-42","title":"добавить проверку аргумента",
        "body":"в deploy.sh отказывать без аргумента",
        "status":"ready","schema_version":1}' >> queue/demo.jsonl

# 4. прогон
./scripts/run-task.sh projects/demo.conf t-42
```

Генератор по умолчанию печатает `--output-format stream-json --verbose`: строка на событие, результат
последней строкой (те же поля, что у `json`); ходы бота видны на дашборде по мере записи
(`/state/logs/<id>/steps.json`). Свой `ORC_GEN_CMD` может печатать и один `json` — раннер берёт
последнюю JSON-строку файла.

## Фаза review: ревьюер → опровергатель

После зелёного гейта раннер делает два чистых вызова `claude -p` без истории генератора (решение
21.09, ресёрч: пара «ревьюер + опровергатель» снимает ложный консенсус, автовызов субагента моделью
не гарантирован, Stop-хук без человека может зациклиться). Оба читают дерево и запускают проверки,
но не правят: изменённое дерево — отказ ревью (`review tree-modified`, статус `blocked`).

- **Ревьюер** получает задачу и дифф, читает чеклисты `.claude/docs/REVIEW*.md` клона, отдаёт JSON по
  схеме `prompts/review-reviewer.schema.json`: находка = серьёзность P1–P3 + AC + место + сценарий.
- **Опровергатель** получает то же плюс находки, каждую подтверждает или опровергает прогоном, добивает
  своё в `extra` (`prompts/review-challenger.schema.json`). Находка без его вердикта считается
  подтверждённой.
- **Итог**: подтверждённая P1 → `blocked`, таблица в `logs/<id>/scratch/NEEDS-OWNER.md`, MR не открыт;
  иначе таблица `logs/<id>/review/review.md` дописывается в MR, задача `done`. Дашборд показывает фазу
  и ссылку «ревью подтверждено/опровергнуто».
- **Маршрут** — поле `"track"` в строке очереди (треки A/B/C из methodology-routing харнесса):
  `REVIEW_TRACKS` (по умолчанию `A B`) идут на ревью, остальные — сразу в MR; без поля — `REVIEW_DEFAULT_TRACK`
  (`A`). Пустое `REVIEW_TRACKS=""` — ревью выключено.
- **Цена**: вход в контекст инстанса ~$0.6 на вызов при 1h-кэше, смоук 21.09 — $1.07 + $0.84 на два
  вызова при $1.10 генератора. `REVIEW_BUDGET_USD` (2.50) на каждый вызов, `REVIEW_MODEL` (пусто —
  модель CLI) режет цену, если ревью хватает модели попроще.
- **Тесты** подменяют вызовы `ORC_REVIEW_CMD` / `ORC_CHALLENGE_CMD`; в `setup()` они `false`, чтобы
  забытая подмена роняла тест, а не звала CLI (21.09: 25 живых вызовов на ~$5 из-под bats).

## Сверка рендера с кадром Figma

`scripts/compare-figma.sh <url> <outdir> <имя>=<ширина>x<высота>:<кадр.jpg> [...]` — headless Chrome
снимает страницу на ширинах кадров, Pillow считает пиксельный дифф с экспортом Figma (блюр 1px гасит
шум антиалиасинга, сдвиги в 1–2px остаются контурами), на выходе `heat/*.png`, `heat/stats.json`
с процентом расхождения и `compare.html` — три колонки, сетка 8px, onion-skin. Нужны Chrome
(`CHROME=` для другого пути), `python3` с Pillow и numpy, поднятая страница. Порог — `DIFF_THRESHOLD`.
Ревью 20.09 на секции hero: 4 % расхождения на desktop, 9 % на mobile — контуры глифов, сдвиг 1–2px.

Живой дашборд прогонов — `./scripts/dashboard.sh` (порт 8765): страница `dashboard/index.html` опрашивает
очередь, `mr/` и JSONL-логи раз в 2 с — фазы с длительностями, цена и ходы, вопрос из `_scratch` у
задач в `blocked`, заметки бота. Две кнопки — «запустить» для `ready` и «вернуть в ready» для
`blocked`/`*-failed`: сервер `scripts/dashboard-server.py` (Python stdlib) зовёт `run-task.sh` в фоне
и `queue_set_status`, переходы держит библиотека очереди. Слушает только `127.0.0.1` и требует
заголовок `X-Orc` — чужая страница в браузере до действий не дотянется. `state` — симлинк на каталог логов.

Сервер — Python 3 из macOS, Node не нужен. Запущенный из терминала он живёт, пока открыт терминал; из
сессии Claude Code — пока жива сессия. Чтобы пережил и то и другое — отвязать от сессии:

```bash
nohup ./scripts/dashboard.sh 8765 > ~/.orchestrator/dashboard.log 2>&1 &
```

Автозапуск при логине — LaunchAgent (ключи по `man launchd.plist`):

```bash
cat > ~/Library/LaunchAgents/local.orchestrator.dashboard.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>local.orchestrator.dashboard</string>
  <key>ProgramArguments</key><array>
    <string>/bin/sh</string><string>-c</string>
    <string>cd "$HOME/Desktop/orchestrator" &amp;&amp; exec ./scripts/dashboard.sh 8765</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/tmp/orchestrator-dashboard.log</string>
  <key>StandardErrorPath</key><string>/tmp/orchestrator-dashboard.log</string>
</dict></plist>
EOF
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/local.orchestrator.dashboard.plist
# снять: launchctl bootout "gui/$(id -u)/local.orchestrator.dashboard"
```

`KeepAlive` перезапускает сервер после падения; путь к репозиторию в plist — свой. Проверка после
логина: `curl -s -o /dev/null -w '%{http_code}' http://localhost:8765/dashboard/` → `200`.

Репозиторий лежит в `~/Desktop` (или `~/Documents`) → агент упадёт с `Operation not permitted`
и будет перезапускаться каждые 10 секунд: фоновым процессам launchd macOS не даёт доступ к этим
каталогам без разрешения (замер 20.09). Два выхода: дать `/bin/sh` доступ в System Settings →
Privacy & Security → Full Disk Access, либо держать репозиторий вне защищённых каталогов.
Снять агент: `launchctl bootout "gui/$(id -u)/local.orchestrator.dashboard"`.


Прогресс печатается в stderr, путь к результату — в stdout. Вывод читается глазами и разбирается скриптом одновременно.

Если целевой репозиторий содержит `.harness.conf`, команды проверок и запретные каталоги берутся оттуда, а не из конфига раннера.

Генератор запускается с `--strict-mcp-config` и пустым списком MCP-серверов: серверы из `~/.claude.json` владельца в прогон не грузятся, боту они недоступны и не нужны. Хуки целевого репозитория тоже выключены (`disableAllHooks`) — гейт зовёт раннер.

## Устройство

| Файл | Ответственность |
|---|---|
| `scripts/run-task.sh` | раннер одной задачи |
| `scripts/lib/queue.sh` | очередь: готовность, статусы, дедуп по хэшу промпта |
| `scripts/lib/log.sh` | события JSONL, метрики прогона агента |
| `scripts/lib/watchdog.sh` | дедлайн на внешнюю команду |
| `scripts/lib/mr.sh` | результат: файл, `glab`, `gh` |
| `scripts/lib/harness.sh` | чтение `.harness.conf`, запретные каталоги, область работы |
| `scripts/lib/ui.sh` | фазы, время, стоимость |
| `hooks/pre-receive.sh` | запрет push в защищённые ветки на стороне bare-репозитория |

Конфиги и очередь лежат в репозитории. Рабочие каталоги задач и логи прогонов живут вне git-дерева, в `~/.orchestrator`.

## Почему сделано так

**Запрет на push в основную ветку живёт в git-хуке, а не в промпте.** Инструкцию модели можно обойти инъекцией из чужого текста, настройку сервера — нет. В локальном варианте это `pre-receive` в bare-репозитории, на живой платформе — protected branch.

**Конфиг целевого репозитория парсится, а не подключается через `source`.** Файл приезжает из клона, и `source` исполнил бы его содержимое до первой проверки.

**Дедлайн реализован свой, потому что утилиты `timeout` на macOS нет.** Ожидание идёт по файлу с кодом возврата, а не по `kill -0` для pid: незажатый процесс отвечает на сигнал успехом. Убивается группа процессов, иначе дочерние процессы агента переживают дедлайн.

**Ошибка агента не читается как «править было нечего».** Упор в лимит бюджета даёт пустой дифф, и первая версия помечала такую задачу выполненной.

**Вопрос владельцу — файл, а не текст ответа.** Агент, которому не хватает входа, пишет вопрос в `_scratch/NEEDS-OWNER.md` рабочего каталога (имя — `NEEDS_OWNER_FILE` в конфиге). Раннер читает файл до гейта, ставит `blocked`, копирует его в лог прогона и MR не открывает. Текст ответа агента раннер не разбирает: формат вывода у генераторов разный, а файл один на всех. Замер 18.09: агент без копирайта придумал текст, признался в ответе — и задача ушла в `done` с MR. Вторичный сигнал того же класса — `permission_denials` в итоговом JSON: в `-p` без хоста вызов `AskUserQuestion` отклоняется молча, раннер читает это поле и тоже ставит `blocked`.

**`set -e` не используется.** У раннера четыре штатных исхода, три из них неуспешные. Падение по `-e` превращало бы их в сбой без записи в лог.

## Ограничения

Одна задача за прогон. Только macOS и Linux. Задачи должны быть узкими: правка в известном месте, результат которой проверяется машиной. «Сделай фичу» этой петлёй не закрывается — ревью-ёмкость человека кончится раньше.

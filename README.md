# orchestrator

Раннер задач для Claude Code. Берёт задачу из файловой очереди, отдаёт её агенту в headless-режиме, проверяет результат машинным гейтом и оставляет ветку. Мерж делает человек.

Написан на bash. Работает на подписке Claude, API-ключ не нужен.

## Статус

Слой 0 закрыт. Петля замкнулась на живой задаче: агент подавил замечание `shellcheck` в чужом репозитории, гейт прошёл, ветка появилась. Стоило $1.02 и 12 ходов модели.

91 тест, полный прогон одной командой. Второго проекта, параллельных прогонов и очереди из трекера пока нет.

## Что делает

```
очередь (JSONL)
  → клон базовой ветки в отдельный каталог
  → claude -p с промптом из задачи, под дедлайном
  → проверка области работы и readonly-зон
  → гейт проекта (lint)
  → полный прогон тестов проекта
  → секрет-скан
  → push ветки
  → MR (файлом или на платформе)
```

Каждая фаза пишет строку в JSONL-лог. Таймлайн прогона собирается одной командой `jq`, тяжёлый вывод фаз лежит отдельными файлами.

## Чего не делает намеренно

Не пушит в базовую ветку. Запрет живёт в `pre-receive`-хуке на стороне git-сервера, а не в инструкции для модели: промпт обходится инъекцией, настройка сервера нет.

Не мержит и не апрувит. Ветка и описание готовятся для человека.

Не создаёт merge request по умолчанию. Бэкенд `file` пишет описание в `.md`, и MR открывает владелец, посмотрев дифф. Для GitLab и GitHub бэкенды есть, но на живой платформе ещё не гонялись.

Не удаляет рабочие каталоги задач. Стёртый каталог означает, что провал нечем разбирать.

Не работает параллельно. Одна задача за прогон.

## Требования

`bash` 3.2 и новее (системного на macOS достаточно), `git`, `jq`. Для тестов `bats` и `shellcheck`. Генератор по умолчанию `claude -p`, но подменяется переменной `ORC_GEN_CMD` на любую команду.

## Быстрый старт

```bash
# 1. локальный remote с гардрейлом: push в main отклоняется хуком
./scripts/make-remote.sh /tmp/target.git main

# 2. конфиг проекта
cat > projects/demo.conf <<'EOF'
REPO_URL="/tmp/target.git"
BASE_BRANCH="main"
BRANCH_PREFIX="orc"
GATE_CMD="npm run lint"
MR_BACKEND="file"
MR_DIR="/tmp/mr"
QUEUE_FILE="queue/demo.jsonl"
DEADLINE_SEC="900"
MAX_BUDGET_USD="1.00"
WRITE_SCOPE="src/features/x"
EOF

# 3. задача в очередь
echo '{"id":"t1","title":"починить типы","body":"...","status":"ready","schema_version":1}' \
  >> queue/demo.jsonl

# 4. прогон
./scripts/run-task.sh projects/demo.conf t1
```

Прогон печатает фазы с временем и стоимостью в stderr. Путь к MR уходит в stdout, поэтому вывод одновременно читается глазами и разбирается скриптом.

Свои проверки: `./scripts/verify-all.sh`.

## Как устроено

| Файл | Ответственность |
|---|---|
| `scripts/run-task.sh` | раннер одной задачи |
| `scripts/lib/queue.sh` | очередь: готовность, статусы, дедуп по хэшу промпта |
| `scripts/lib/log.sh` | события JSONL, метрики прогона генератора |
| `scripts/lib/watchdog.sh` | дедлайн на внешнюю команду |
| `scripts/lib/mr.sh` | адаптер MR: `file`, `glab`, `gh` |
| `scripts/lib/harness.sh` | контракт `.harness.conf`, readonly-зоны, область записи |
| `scripts/lib/ui.sh` | фазы, время, стоимость в stderr |
| `hooks/pre-receive.sh` | гардрейл push на стороне bare-репозитория |

Конфиги и очередь лежат в репозитории. Рабочие каталоги задач и логи прогонов живут вне git-дерева, в `~/.orchestrator`.

## Решения, которые стоит знать до чтения кода

**Конфиг целевого репозитория парсится, а не сорсится.** `.harness.conf` приезжает из клона, и `source` исполнил бы его содержимое до первой проверки. Тест на это есть.

**Вотчдог свой, потому что `timeout` на macOS отсутствует.** Ожидание идёт по файлу с кодом возврата, а не по `kill -0` для pid: незажатый зомби отвечает на сигнал успехом. Убивается группа процессов, иначе внуки генератора переживают дедлайн.

**Область работы проверяется по диффу.** Промпт просит агента держаться модуля, а `WRITE_SCOPE` обязывает. Всё, что вне области, останавливает задачу до гейта.

**Ошибка генератора не читается как «править было нечего».** Упор в бюджет даёт пустой дифф, и первая версия помечала такую задачу выполненной. Теперь проверяется `is_error` и `subtype` из JSON.

**`set -e` не используется.** У раннера четыре штатных исхода, три из них неуспешные. Падение по `-e` превращало бы их в необъяснимый сбой без записи в лог.

## Что закреплено тестами

Push в защищённую ветку отклоняется, ветка не удаляется, история не перезаписывается. Готовность очереди сверяется с файлом-эталоном. Обрыв записи не портит очередь. Пустой вывод генератора и неразбираемый вывод логируются отдельными событиями. Задача без промпта блокируется до запуска модели.

Каждый инвариант проверен мутацией: правка кода, которая его снимает, роняет ровно тот тест, который за него отвечает.

## Что не проверено

Push по токену в настоящий GitLab или GitHub. Бэкенды `glab` и `gh`. Поведение при заполненном диске и при `REPO_URL` по SSH. Параллельные прогоны.
